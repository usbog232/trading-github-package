# Hyperliquid Trading System Skeleton

目标：为老板的 HYPE / Hyperliquid 合约交易建立一套以风险控制为核心的 API 交易系统。

## 核心原则

1. 风险 > 收益
2. 无计划，不交易
3. 无止损，不交易
4. 高风险环境，不交易
5. 连续亏损 >= 3 单，强制停止交易
6. 单笔总风险默认控制在账户 3% 左右，最大不超过 8%

## 第一阶段目标

- 打通行情抓取
- 输出标准化交易分析
- 建立风控闸门
- 暂不默认自动实盘执行

## 目录结构

- `config/` 配置文件
- `data/` 市场快照、交易记录、复盘日志
- `logs/` 运行日志
- `src/` 系统源码
- `tests/` 基础测试

## 组件

- `fetcher.py`：行情、K线、账户、订单数据获取
- `analyzer.py`：趋势、结构、指标、多周期共振分析
- `risk_engine.py`：仓位控制、风险审查、交易拦截
- `executor.py`：下单、止损止盈、撤单、状态查询
- `journal.py`：交易记录与复盘
- `main.py`：主入口，串联整个流程

## 风控说明

- 单笔风险采用更贴近实战的总风险口径：止损亏损 + 手续费 + 预估滑点
- 默认目标风险约 3%
- 单笔最大风险阈值为 8%
- 超过 8% 的计划应视为禁止执行

## 测试单模式

- `test_order_mode=true` 时启用测试单例外规则
- 单笔测试单最大名义仓位：15 USDC
- 单笔测试单最大亏损：账户 1%
- 每日测试累计亏损上限：5 USDC
- 测试单必须单独记录日志

## 默认工作模式

- `paper`：只分析，不下单
- `manual_confirm`：分析后等待人工确认
- `semi_auto`：满足条件后允许半自动执行

默认使用 `manual_confirm`。

## 输出模板

1. 市场状态（趋势/震荡/高风险）
2. 是否建议交易（是 / 否 / 等待）
3. 交易方向（多 / 空 / 无）
4. 入场位置
5. 止损位置
6. 止盈目标
7. 仓位建议
8. 风险等级（低 / 中 / 高）
9. 备注（关键逻辑）

若条件不满足：

> 当前无优势，不建议交易
